# إصلاح إنشاء الحسابات، حذف الحسابات والطلاب، وتغيير كلمة المرور

## سبب المشكلة (تم التحقق منه)
لم يُنشأ أي حساب جديد منذ يونيو. إنشاء الحساب يتم حاليًا من المتصفح عبر «تسجيل حساب جديد»، وهذا يبدّل جلسة المشرف العام إلى جلسة الحساب الجديد فورًا، فتفشل الخطوات التالية (تعيين الدور، المادة، الصفوف) لأنها تُنفذ بصلاحيات المعلم الجديد، وتظهر رسالة خطأ أو حساب ناقص. كما أن حماية كلمات المرور المسرّبة ترفض الكلمات الشائعة جدًا دون رسالة واضحة.

## ما سيتم بناؤه

### 1. إصلاح إنشاء حسابات المعلمين
- نقل إنشاء الحساب إلى دالة خادم آمنة (للمشرف العام فقط) تُنشئ المستخدم مؤكَّدًا مباشرة دون تبديل جلسة المشرف.
- الدالة نفسها تضبط الدور والبريد الاختياري والمادة والصفوف في خطوة واحدة.
- رسائل خطأ عربية واضحة: اسم مستخدم مكرر، كلمة مرور ضعيفة/شائعة، أقل من 6 خانات.
- إزالة تحذير «قد يتم تسجيل دخولك بالحساب الجديد» من النافذة.

### 2. حذف حسابات المستخدمين
- زر «حذف الحساب» في بطاقة كل مستخدم (للمشرف العام فقط) مع نافذة تأكيد.
- دالة خادم تحذف الحساب نهائيًا مع كل سجلاته: المخالفات والسلوكيات الإيجابية والتقارير الأكاديمية التي سجّلها، وسجلات النقاط والإشعارات وإسنادات المواد والصفوف.
- منع المشرف من حذف حسابه الحالي.

### 3. حذف الطلاب بالتحديد الجماعي
- في صفحة الطلاب: مربع اختيار لكل طالب + «تحديد الكل» في رأس الجدول.
- شريط يظهر عند وجود تحديد: «حذف المحدد (N)» مع تأكيد.
- يبقى زر الحذف الفردي كما هو.

### 4. تغيير كلمة المرور للمعلم بعد الدخول
- خيار «تغيير كلمة المرور» في قائمة المستخدم أعلى الصفحة (متاح لكل الأدوار).
- نافذة: كلمة المرور الحالية، الجديدة، التأكيد. الحد الأدنى 6 خانات (أرقام أو أحرف أو مزيج).
- عند أول دخول للمعلم بعد إنشاء حسابه، تظهر النافذة تلقائيًا بتنبيه ودّي (يمكن تخطيها).
- تبقى حماية كلمات المرور المسرّبة مفعّلة، مع رسالة عربية واضحة إذا رُفضت كلمة شائعة.

## التفاصيل التقنية
- ملف جديد `src/lib/users.functions.ts`: `adminCreateUser` و`adminDeleteUser` بـ `requireSupabaseAuth` + تحقق من دور admin ثم استخدام Auth Admin API (`createUser` مع `email_confirm: true` / `deleteUser`) عبر عميل الخدمة المُحمَّل داخل الـ handler.
- الحذف المتسلسل: حذف صفوف `violations`, `positive_behaviors`, `academic_reports`, `point_transactions`, `notifications`, `teacher_subjects`, `teacher_classes`, `user_roles`, `profiles` حيث `created_by`/`user_id` = المستخدم، ثم حذف المستخدم من المصادقة.
- `teachers.tsx`: استبدال `supabase.auth.signUp` باستدعاء الدالة، إضافة زر حذف + AlertDialog.
- `students.index.tsx`: حالة `selectedIds`، checkbox لكل صف، حذف جماعي بـ `.in("id", ids)`.
- عمود جديد `profiles.must_change_password boolean default false` يُضبط true عند إنشاء الحساب ويُصفَّر بعد التغيير؛ `app-header.tsx` يعرض نافذة التغيير باستخدام `supabase.auth.updateUser({ password, current_password })`.
- لا تغيير على إعدادات الحماية (HIBP يبقى مفعّلًا، الحد الأدنى 6).
